# Gardener Rules

## Protected Modules

- `src/domain/achievements.ts` because Defines streak and time-based unlock logic, which the spec requires to be derived deterministically from the calendar and not the current date.
- `src/domain/flames.ts` because Holds the flame catalog where each flame maps to exactly one achievement and Amber is always unlocked by default.
- `src/data/entriesStore.ts` because Enforces the 1-5 integer score range and the no-future-date rule, and persists scores that must survive restarts.
- `src/components/Bonfire/flameModel.ts` because Maps strength to on-screen flame size through the soft cap and distinguishes unlit, lit, and out states that the spec defines.
- `src/components/Bonfire/Embers.tsx` because Renders embers that the spec says appear only while lit and must not appear in the out state.
- `src/hooks/useSettings.ts` because Persists the flame color choice (Amber default) across restarts, which the spec treats as required behavior.
- `src/theme/palettes.ts` because Defines the Amber, Crimson, and Sapphire color ramps and the embered variants that the spec fixes.
- `src/screens/BonfireScreen.tsx` because Owns the cold-start loading placeholder that must hold until saved scores load, and the score-entry flow that must not discard entries made during loading.

## Never-Touch Paths

- `specs/**` because Product specs are the authoritative statement of scope and fix/no-fix policy, so automated maintenance must not rewrite them.
- `gardener/**` because This is the maintenance tool's own directory, so the tool should not modify its own policy or runtime.
- `src/components/Bonfire/Flame.tsx` because The spec forbids reducing flame fidelity for performance, so automated changes that simplify the rendering would violate the requirement.
- `src/domain/fire.ts` because src/domain/fire.ts (computeFire) must stay unchanged; richer metrics live in a new module. (from `specs/002-achievement-flame-unlocks/tasks.md#Tasks: Achievement-Locked Flame Styles`)
- `__tests__/fire.test.ts` because __tests__/fire.test.ts must stay unchanged alongside src/domain/fire.ts. (from `specs/002-achievement-flame-unlocks/tasks.md#Tasks: Achievement-Locked Flame Styles`)
- `BonfireDesign/**` because BonfireDesign reference files (flame-profiles.js, flame-renderer.jsx, flame-catalog.css, screenshots) are required reference inputs and are not to be modified by the app change. (from `specs/004-flame-visual-profiles/plan.md#Implementation Plan: Flame Visual Profiles`)
- `**/.env*` because secrets must never be modified by Gardener.
- `**/secrets/**` because secret material requires human handling.

## Autonomous Fixes Allowed

- `lint_format`: kept from the current constitution
- `dependency_patch`: kept from the current constitution
- `tests`: Adding Jest tests for pure domain logic such as fire state and achievements is low-risk and matches the spec's test-first approach without changing app behavior

## Assisted Fixes Allowed

- `refactoring`: kept from the current constitution
- `complexity_reduction`: Simplifying functions in the Skia flame and fire-state code can change visual or derived-state behavior, so it needs review and must preserve the no-fidelity-loss rule
- `layer_violation_repair`: Breaking import cycles between domain, data, and component layers touches persistence and rendering boundaries, so a maintainer should review the result
- `requirement_mismatch`: Changes to the locked-selection guard touch the equip behavior and should be reviewed by a human before merging (source: specs/003-ui-flame-polish/tasks.md#Tasks: UI & Flame Polish Fixes)

## Advisory-Only Areas

- `security_sensitive_code`: Score validation and local AsyncStorage persistence are the only sensitive paths here, so the tool should advise on them and not open PRs
- `tenancy`: kept from the current constitution
